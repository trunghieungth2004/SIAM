## 1. BACKGROUND AND MOTIVATION

### 1.1 Executive Summary

This proposal outlines the development of a high-performance, resilient predictive maintenance platform, SIAM (Smart Industrial Asset's longevity Monitor). The system is designed to monitor industrial equipment (represented by a demo fan machine) in real-time, detect anomalous behavior, and predict equipment health.

This solution leverages a hybrid architecture, combining a powerful edge device (Raspberry Pi 5 with a Coral TPU) with a secure, serverless AWS backend. The edge device runs AWS IoT Greengrass to manage two distinct applications:

1. A native C-based datalogger that reads directly from hardware sensors (MPU-6050, INA219, DS18B20) and writes data to Greengrass Stream Manager.
2. A Docker-containerized Python ML inference application that reads from Stream Manager, performs real-time anomaly detection using the Coral TPU, and publishes predictions back to the cloud.

The cloud backend uses Greengrass Stream Manager to buffer sensor data locally and publish to AWS IoT Core. Data is ingested via an IoT Rule triggering a Lambda function that stores records in DynamoDB and S3 Data Lake. The system features a REST API via API Gateway with x-api-key authentication, rate limiting, and automatic monthly key rotation. A fully automated MLOps pipeline using EventBridge and SageMaker retrains models bi-weekly and redeploys to the edge. A public web dashboard hosted on S3 provides real-time monitoring with Swagger/OpenAPI documentation for the REST API.

### 1.2 Project Success Criteria

Success for this project will be measured by the following criteria:

- **Functional Cloud Backend**: All AWS infrastructure (S3, DynamoDB, Lambda, API Gateway, etc.) is successfully deployed via the `./AWS.sh` script.
- **Operational Edge Device**: The Raspberry Pi is successfully provisioned with AWS IoT Greengrass using the setup script.
- **Reliable Data Collection**: The native C datalogger component successfully reads from all sensors (MPU-6050, INA219, DS18B20) and logs data to the local Stream Manager.
- **Offline Resilience**: The system can successfully buffer data on the Pi during a network outage and automatically sync to the cloud upon re-connection (zero data loss guarantee).
- **Trained ML Model**: An initial anomaly detection model is successfully trained in Amazon SageMaker using a locally-collected 24-hour dataset.
- **End-to-End Inference**: The full pipeline is demonstrated: the Dockerized inference component on the Pi successfully loads the trained model, reads from the local stream, performs real-time inference using the Coral TPU, and publishes predictions.
- **Automated MLOps**: The EventBridge-driven retraining pipeline works: it automatically triggers bi-weekly to train a new model and deploy it back to the Greengrass device without manual intervention.
- **Secure API**: API Gateway with x-api-key authentication, rate limiting (10 req/s, burst 20, 10k daily quota), and automated monthly key rotation.

### 1.3 Assumptions

- A stable 5V/5A USB-C PD power supply is available for the Raspberry Pi 5.
- A stable internet connection is available for the Raspberry Pi for cloud communication.
- A stable internet connection is available on the Arch Linux management machine.
- An AWS account with Administrator-level permissions is available to run the setup scripts.
- All required hardware (Pi 5, Coral TPU, sensors, breadboard, etc.) is sourced and available for development.
- The `./AWS.sh` setup script is available for infrastructure deployment.

## 2. SOLUTION ARCHITECTURE / ARCHITECTURAL DIAGRAM

### 2.1 Technical Architecture Diagram

[IMAGE: SIAM_Architecture.drawio]

**AWS Services Used:**

- **Edge**: AWS IoT Greengrass (Core, Stream Manager, Component Deployments)
- **Ingestion**: AWS IoT Core (MQTT Broker, Rules)
- **Compute**: AWS Lambda (Ingestion, Query, Retrain, Deploy, Rotate)
- **Storage**: Amazon DynamoDB, Amazon S3 (Data Lake, Model Artifacts, Web Hosting)
- **API & Security**: API Gateway (REST API, x-api-key auth, rate limiting), IAM
- **Machine Learning**: Amazon SageMaker (Training Jobs)
- **Automation**: Amazon EventBridge (Bi-weekly retraining, Monthly key rotation, Deployment triggers)
- **Monitoring**: Amazon CloudWatch, Amazon SNS
- **Reliability**: Amazon SQS (Dead-Letter Queue)

### 2.2 Technical Plan

The architecture is composed of the following component groups:

**Edge Device:** A Raspberry Pi 5 running Raspberry Pi OS Lite. AWS Greengrass Core runs as the main agent. Two primary applications are deployed as components:

1. **datalogger**: A native C application that reads from I2C/1-Wire sensors and publishes data to a local Stream Manager stream.
2. **inference**: A Docker container running Python, which subscribes to the local Stream Manager stream, loads the ML model, performs inference on the Coral TPU.

**Cloud Pipeline:** Greengrass Stream Manager → IoT Core → IoT Rule → Ingestion Lambda. The Lambda writes to DynamoDB and S3.

**Web Application:** A vanilla JavaScript app on S3 Static Website. The app fetches data from API Gateway (with x-api-key authentication), which triggers the Query Lambda to read from DynamoDB. The endpoint is secured with rate limiting and automatic monthly key rotation. Interactive API documentation is provided via Swagger UI.

**MLOps Pipeline:** An EventBridge rule runs bi-weekly (every 14 days), triggering the Retrain Lambda. This Lambda aggregates up to 500 samples from S3 and starts a SageMaker Training Job. Upon job completion, EventBridge triggers a Deploy Lambda which creates a new Greengrass Deployment to send the updated model to the Pi.

**Security Automation:** An EventBridge rule runs monthly (every 30 days), triggering the Rotate Lambda. This Lambda creates a new API key, updates the usage plan, deletes the old key, and updates the frontend files in S3 with the new key.

**Reliability:** The Ingestion Lambda is backed by an SQS Dead-Letter Queue (DLQ) to capture and hold any failed messages, ensuring no data is lost.

### 2.4 Security Considerations

**Device Security:** The Raspberry Pi authenticates with AWS IoT Core using X.509 client certificates. No long-lived AWS credentials (access keys) are stored on the edge device.

**API Security:** The API Gateway acts as a secure front-door, protecting the Query Lambda. Access is restricted using x-api-key authentication with:
- Rate limiting: 10 requests/second, burst capacity 20
- Daily quota: 10,000 requests
- Automated monthly key rotation via EventBridge Lambda
- CloudWatch monitoring for anomalous usage patterns

**Data Security:** All data-in-transit is encrypted (HTTPS, MQTT over TLS). Lambda functions access resources via IAM roles with least-privilege permissions.

**Credential Management:** All sensitive credentials are stored in AWS Secrets Manager and retrieved at runtime by Lambda functions.

### 3.3 Path to Production

This project is a **Production-Ready Prototype**. To move to a full production deployment, the following steps would be taken:

**Hardware Finalization:** Move the sensor array from a breadboard to a dedicated PCB (Printed Circuit Board) to create a robust, manufacturable, and reliable hardware unit.

**Scaling Architecture:** Implement the "Hub-and-Spoke" model. This would use low-cost ESP32s as "Spoke" dataloggers, transmitting data locally to a central Raspberry Pi "Hub". The Hub would aggregate data and run inference before sending a single, processed data stream to the cloud.

**CI/CD Pipeline:** Integrate the shell scripts (AWS.sh) into an automated MLOps CI/CD pipeline. This pipeline would be responsible for automatically training, versioning, and deploying new models and infrastructure updates.

**Security Hardening:** Implement Amazon Cognito for user authentication on the web dashboard and enforce fine-grained IAM policies across all services.

**Hardware Tiers for Production:**

- **High-End (As-Designed)**: Pi 5 + Coral TPU.
  - Pros: Extremely fast, real-time inference on the edge. High-throughput data logging.
  - Cons: Highest cost, library complexity for TPU (solved by our Docker approach).

- **Mid-Range**: Pi 5 (no TPU).
  - Pros: All-in-one solution with a powerful CPU for ML inference. No need for a separate TPU.
  - Cons: Higher cost and power consumption. Inference would be slower than TPU-accelerated.

- **Low-End**: Pi 4 / Pi Zero 2W.
  - Pros: Very low cost.
  - Cons: Slower C datalogging. On-device inference would be too slow to be practical. This architecture would likely need to be modified to send data to a cloud-hosted SageMaker endpoint for inference, losing offline capabilities.

## 4. EXPECTED AWS COST BREAKDOWN BY SERVICES

**Infrastructure Costs (Monthly, Production Single-Device Deployment):**

- **AWS Lambda**: ~$1.20
  - 5 Lambda functions (Ingestion, Query, Retrain, Deploy, Rotate)
  - Estimated 50,000 invocations/month
  - ~500 GB-seconds compute time

- **AWS IoT Greengrass**: $0.00 (Free for up to 10 devices)

- **AWS IoT Core**: ~$2.50
  - 1 device sending 1 msg/min = ~43,200 msgs/month
  - Connectivity + messaging + rules engine

- **Amazon DynamoDB**: ~$3.75
  - On-demand pricing for 43,200 writes/month
  - ~5,000 reads/month (dashboard queries)
  - 5 GB storage

- **Amazon S3**: ~$1.50
  - Data Lake: 10 GB storage
  - Model artifacts: 2 GB
  - Static website hosting

- **API Gateway**: ~$2.00
  - REST API with 5,000 requests/month
  - Rate limiting and usage plans

- **Amazon SageMaker**: ~$4.80
  - Bi-weekly training (2 jobs/month)
  - ml.m5.xlarge instance: 30 minutes per job

- **Amazon EventBridge**: ~$0.10
  - 3 scheduled rules (retrain bi-weekly, rotate monthly, deploy on completion)

- **Amazon CloudWatch**: ~$2.50
  - Log ingestion: ~5 GB/month
  - Metrics and dashboards

- **Amazon SNS**: ~$0.15
  - ~100 notifications/month (alerts, automation)

**Total Monthly Cloud Cost**: ~$18.50 - $20.00

- **AWS Lambda**: $0.00 (1 million requests/month free)

- **Amazon DynamoDB**: $0.00 (25 GB storage + 25 WCU + 25 RCU always free)
- **Amazon S3**: ~$0.10 (5 GB storage + 20,000 GET + 2,000 PUT requests)
- **API Gateway**: $0.00 (1 million API calls/month free for 12 months)
- **Amazon SageMaker**: ~$0.27 (250 hours ml.t3.medium/month for first 2 months)
- **Amazon CloudWatch**: $0.00 (5 GB log ingestion + 10 custom metrics always free)
- **EventBridge & SNS**: $0.00 (covered by free tier)

**Total Monthly Cost (First 12 Months)**: ~$1.00 - $2.00
